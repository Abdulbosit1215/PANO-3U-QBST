# PANO-3U Communication Protocol Specification

Version B / 2026-09

## 1. Inter-Board Link (OBC ↔ CM4 Payload Computer)

- Physical: UART, 115200 8N1, 3.3V level, over stack bus J1 (Pin 13/14)
- Frame format (HDLC-style):

```
[0x7E][CMD:1B][LEN:1B][PAYLOAD:0~255B][CRC16-CCITT:2B][0x7E]
Escape: if payload contains 0x7E -> 0x7D 0x5E; 0x7D -> 0x7D 0x5D
```

### Command Table (OBC → CM4)

| CMD | Name | Payload | Description |
|---|---|---|---|
| 0x01 | PING | — | Heartbeat, CM4 must ACK within 1 s |
| 0x02 | TIME_SYNC | uint32 epoch | Time sync |
| 0x03 | SHOOT | uint8 burst, uint16 interval_s | Panoramic capture |
| 0x04 | VIDEO_START | uint16 duration_s, uint8 fps | Start panoramic video |
| 0x05 | VIDEO_STOP | — | Stop recording |
| 0x06 | TIMELAPSE | uint16 interval_s, uint16 count | Time-lapse mode |
| 0x07 | GET_STATUS | — | Query payload status |
| 0x08 | FILE_LIST | uint16 offset | Paged file list |
| 0x09 | FILE_PREP | uint32 file_id | Prepare file for downlink |
| 0x0A | SHUTDOWN | — | Safe payload shutdown (OBC disables PAYLOAD_EN next) |
| 0x10 | PARAM_SET | key:1B + value:4B | Set parameters (exposure/gain/bitrate, etc.) |

### Responses (CM4 → OBC)

| CMD | Name | Payload |
|---|---|---|
| 0x81 | ACK | original CMD + status |
| 0x87 | STATUS | see below |
| 0x88 | FILE_LIST_RESP | count + [file_id:4B, size:4B, ts:4B]×N |
| 0x89 | FILE_PREP_RESP | file_id, total_chunks:2B, chunk_size:2B, file_crc32:4B |

STATUS payload (24B):
`mode:1B, cam0_ok:1B, cam1_ok:1B, temp0:int8, temp1:int8, disk_free_mb:uint16, vbat_mv:uint16, shooting:1B, pending_files:uint16, uptime_s:uint32, last_err:1B, reserved:6B`

## 2. UHF Downlink (Spacecraft → Ground)

- Physical: 437 MHz, GFSK 9600 bps, AX.25 UI frame
- AX.25 addressing: source `NOCALL-11` (spacecraft), destination `NOCALL-0` (ground), `PID=0xF0`

### Downlink Packet Types (first byte of AX.25 Info field)

| Type | Name | Structure | Timing |
|---|---|---|---|
| 0x01 | Beacon telemetry | [type][seq:2B][OBC telemetry 32B][CM4 STATUS 24B][CRC32] | Every 30 s |
| 0x02 | File chunk | [type][file_id:4B][chunk_no:2B][total:2B][data:N][CRC32] | Continuous during pass |
| 0x03 | File list | Same as FILE_LIST_RESP | On ground request |
| 0x04 | Event log | [type][ts:4B][code:1B][data:8B] | On anomaly/mode switch |

### Resume and Selective Retransmission

- File chunk size: 200 bytes, each chunk checked by CRC32.
- Ground station records received bitmap by `file_id`.
- End of pass: missing chunks can be requested in uplink command frame or at next pass start.
- Max 65535 chunks/file (~13 MB). A compressed panorama (~5 MB) is ~25000 chunks.

### Uplink (Ground → Spacecraft)

| CMD | Name | Description |
|---|---|---|
| 0x21 | REQ_MISSING | `file_id + bitmap_offset + missing_chunk_list` |
| 0x22 | SET_MODE | Forced mode switch (dual confirmation) |
| 0x23 | SCHEDULE | Upload capture schedule (up to 32 entries: `[epoch, cmd, param]`) |
| 0x24 | PARAM_SET | Same as inter-board `0x10` |

## 3. Error Codes

`0x00 OK; 0x01 cam0 fault; 0x02 cam1 fault; 0x03 storage full; 0x04 storage I/O error; 0x05 encoder error; 0x06 over-temperature; 0x07 invalid parameter; 0x08 link timeout`
